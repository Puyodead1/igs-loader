# IGS E2200: the board and the IGS036 protocol

Reversed from Percussion Master 3 M107FA (`PM3-OS`, `PowerOn`, `pm3` with
dynamic symbols).  Disks are in `IGS_ROFS_REVERSE_ENGINEERING.md` (E2200),
constants in `IGS_KEYS.md`.  The loader's implementation is
`machines/e2200/` plus the game plugin `games/percussionmaster3/`.

## The board

The PC side is the E2100's: a 2.6.32.8 "James" kernel (`v1.9.100-rc17`,
2011/12, with the string `E2200 BIOS V1.0.0 (20111207)`) with `igs_rofs` built
in, an NVIDIA GL stack, and the FPGA card behind `/dev/pccard0` with
its IGS036 ("A36").  The game links the same `FPGA_Comm_*` / `P2A_*` /
`FPGA_AES_*` library as Hero of Robots: the same ioctls, BARs, boot
handshake (`IGS_E2100_PROTECTION.md`; the upload key is `PM3FA Start
Now!`, the 512 KB image `A36ROM` in the executable) and request/response
transport.  So `machines/e2200` is `machines/e2100` under its own name.

What is new is behind the IGS036: the drum I/O board (keys, coin, twelve
drum sensors with levels, lamps), relayed as message 3; the chip's NVRAM
(sensor thresholds, coin record); the keys of the game's encrypted charts;
and the screen flow.

| Device | Use |
| --- | --- |
| `/dev/pccard0` | the FPGA card and the IGS036 |
| `/dev/video0..9` | the camera ("CCD", V4L); without it the game warns at start-up and skips photos |
| `/dev/input/event*` | OIS joysticks, unused |
| network | game, patch and FTP servers (`rewrite/net*.cfg`) |
| display | X.org at 1280x720 (`etc/X11/xorg.conf`); the game's Ogre window is fullscreen at the screen's size, its menus are laid out for 1280x720 (list `env` `IGS_SCREEN`) |

## Executable encryption

`/PM3/PowerOn` is decrypted by the kernel's `/bin/uudecode` (FPGA cipher,
the key string `Hello-Percussion` sent to the FPGA, as Scratch's
`/bin/unrar`).  `PowerOn` (`sub_804B61D`) decrypts `../exe/pm3`:
- **Header:** 4 bytes; the key id is bit 3 of byte 0, bit 2 of byte 1, bit
  1 of byte 2 and bit 6 of byte 3 (weights 1, 2, 4, 8).
- **Key:** entry id of a 16-byte table in `PowerOn` (10 keys, repeated for
  ids 10..15), loaded into the FPGA.
- **Body:** from offset 4, the FPGA cipher in 512 KiB pieces.
- **Trailer:** the last 12 plaintext bytes: a random word, the plain size,
  the key id again.

`pm3` uses key id 5.  Only the cipher's output mask matters to an emulated
FPGA; the masks are recovered from known plaintext (an ELF header,
`IGS_KEYS.md`).  The rom-set builder's `poweron` step does this.

## IGS036 transport

`Igs036P2A::SendData` / `ReadData`, on the E2100 request/response
transport (BAR1 word 0 = total bytes, BAR0 = the frame).  Both sides start
at BAR0 + `off` (random padding words before it):

| | Game → chip | Chip → game |
| --- | --- | --- |
| `+0` | word, low byte = `r` + the data's byte sum | word, low byte = `echo` + the data's byte sum |
| `+4` | word, low byte = `r` (random) | word, low byte = `echo`: the game's last `+0` byte |
| `+8` | data | word, low nibble = the next `off` |
| `+12` | | data |

A wrong `echo` or sum and the game spins forever.  The game waits for each
reply (at most 800 bytes) before it sends again.

The data is RC4 (`rc4_CypherKey` / `rc4_CypherData`): one S-box kept
between messages, `i` and `j` reset per message.  The game's first message
(`Game::iIgs036_Init`, type 0 with 8 random bytes) is encrypted after the
key schedule on `PM3   IGSA36`; then the schedule runs on those 8 bytes.
Every later message both ways continues from there.

Inside, a list of `[type u32][length u32][data]`.

**Game → chip:**

| Type | Data |
| --- | --- |
| 0 | 8 random bytes: the RC4 key |
| 1 | 144 bytes: the 36 state objects (`GameProcess *`, null for unused ids) |
| 2 | 4 bytes, each frame: the state's status (1 running, 2 done); or 36 bytes at its end (below) |
| 3 | 8 bytes, each frame: I/O board output (lamps, meter pulse), byte sum at 5 |
| 4 | the chart keys are wanted |
| 6 | 32 bytes: a chart's file name; its cut bytes are wanted |
| 8 / 10 / 11 | sensor thresholds wanted / all twelve set / one set (index, max, min, default, current) |
| 12, 19 | start-up words |
| 14 | 4 random bytes: the stored network data is wanted (answer: 15) |
| 16 | 16 bytes to keep: `{store id, MAC, 0}`, already FPGA-encrypted (`PercussionMaster3_Online.md`) |
| 17 | the coin record is wanted |

**Chip → game** (`Game::iIgs036_RecvCmdPrcess`):

| Type | Data |
| --- | --- |
| 2 | 4 bytes: the current state object |
| 3 | 20 bytes: the I/O board (below) |
| 5 | 320 bytes: 10 chart keys, 32 bytes each (16 used) |
| 7 | 16 bytes: the requested chart's cut bytes |
| 9 | 192 bytes: twelve sensor thresholds {max, min, default, current} |
| 13 | 12 bytes: version (word 0 FPGA: bits 24..29 major, 17..23 minor, bit 30 set = not burnt; word 1 IGS036 fuses, bits 0, 1 set = not burnt; word 2 IGS036 version) |
| 15 | 16 bytes: message 16's data as kept (zero: not registered); the game decrypts it.  Until it comes the game never connects |
| 18 | 172 bytes: coin record (30 + 12 words, a total) |

## The I/O board (message 3)

| Bytes | |
| --- | --- |
| 0..3 | key-in bits: 0..23 the two number pads, 24 test, 25 service, 26 coin |
| 4 | unused |
| 5..16 | the twelve sensors' levels (0..255) |
| 17..18 | sensors hit (bit = sensor) |
| 19 | the byte sum of 0..18 |

Sensors 0..5 are player 1's, 6..11 player 2's, each: little drum 1
(blue), little drum 2 (red), the drum's left rim, left half, right half,
right rim (the I/O test's 1..6).  The chip decides "hit": the level against
the sensor's current threshold.  The game counts a press from its second
frame (`GameKey::blIsKeyPressPulse`).

Key-in bits for the number pads (0..9, then the two extra keys `*`, `#`):
player 1 6, 12, 13, 14, 15, 0, 1, 2, 3, 4, 5, 7; player 2 10, 16..23, 8,
9, 11.

## Charts

`media/script_AES/<song>_<level>.enccut` (`BandScript::iLoadBandFile`,
`AES::iAESDecrypt`): `PowerOn`'s format, with the key from the chip's
table (message 5), and the first 16 bytes (the header and the first 12
cipher bytes) cut off: the chip sends them per chart (message 7, after the
game names it in message 6).  `SongList.enc` is whole and uses a key
built into `pm3`.  A file in `rewrite/script_download` (`<name>.enc`, whole)
replaces one in `script_AES`.

All ten keys' masks were recovered from the charts themselves (the text's
byte statistics, then checked on every chart's trailer: all 814 decrypt
under exactly one key and name it).  Key 5's mask is `pm3`'s, so the chip's
table is taken to be `PowerOn`'s.  Every chart's first line is
`#------ BASE DATA ------`; its first 16 bytes, encrypted, give the cut
bytes, and the 4 cipher bytes still in each file match for all 814.

## The screen flow

The game runs the current state object's `Init`, `Process` and `End`; at
its end it reports 36 bytes: `[status, id, six results, flags]`, flags
bit 0 = test pressed.  Values are padded with random multiples (`x + 15 *
r`, `x + 2 * r`, `x + 3 * r`).  The chip then names the next state.  The
rebuilt routing (`games/percussionmaster3`, `next_state`):

| Id | State | Next |
| --- | --- | --- |
| 1 | Logo | 3 |
| 3 | Coinpage | result 0 = 1: 4; 0 (timed out): 15, the demo song |
| 4 | Login | 7 |
| 7 | SelType | 8 |
| 8 | SelMode | 13 (11 or 10 for modes 1, 2: guessed) |
| 10, 11, 13 | SelEV, SelSkill, SelLevel | 14 |
| 14 | SelSong | 15 |
| 15 | Stage | 17; 23 after the demo |
| 17 | Resultp | `Resultp::CheckNext` (result 1 % 15): 1, 2 another round (14); 4 32; 5 30; else 19 |
| 19 | FinalResult | 20 |
| 20 | House | `House::CheckNext` (result 1): 0 21 (photo); 1, 2, 6 a player continues (8); 3 32; 4 30; else 23 |
| 21 | Photo | 23 |
| 23 | Rank | result 0 % 3 = 1 (a game): 25; else 1 |
| 25 | Thank | 1 |
| 30, 32, 35 | InfoDragon, InfoMatch | 19 |
| 31 | Setting (operator menu) | 1 |

Online (`PercussionMaster3_Online.md`, "Screen flow online"): Login to 6
Sign, 28 Match after the login and in the attract, 23 Rank to 33 netrank,
House 1 / 3 / 4 to the second player's House.  Unused: 26 SelRole (no
caller sets its player).  The game itself decides rounds, continues and
the end (`Resultp::CheckNext`, `House::CheckNext`); the chip only follows.

The plugin keeps message 16's network data in `rewrite/igs036.nv` and
answers message 14 with it (message 15).
