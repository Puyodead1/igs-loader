# IGS E1000: the board and the IGS027A command protocol

Reversed from Percussion Kids M105CN (`pkids`, built 2005, symbols kept).
Disks are in `IGS_ROFS_REVERSE_ENGINEERING.md` (E1000), constants in
`IGS_KEYS.md`.  The loader's implementation is `machines/e1000/` plus the
game plugin `games/percussionkids/`.

The board is an AMD Geode GX2 PC (Linux 2.4.24, uClibc 0.9.26, BusyBox).
The game draws with the GX2's 2D engine itself (AMD's Durango `gfx_*`
library linked in, a DirectDraw-like layer over it); SDL is only used for
sound.  The protection is an **IGS027A** ("a27") on a PC card behind
`/dev/pccard0`, and it runs the game: the executable only executes the
command lists the chip sends.

## Devices

| Device | Use |
| --- | --- |
| `/dev/mem` | `mmap` of the GX2's DC (16 KB), GP (16 KB), VP (4 KB) registers and the frame buffer, at the physical addresses in the PCI BARs |
| port I/O (`iopl(3)`) | PCI configuration `0xCF8`/`0xCFC`; VSA virtual registers `0xAC1C`/`0xAC1E` |
| `/dev/cpu/0/msr` | GeodeLink MSRs: `lseek(msr)`, 8-byte `read`/`write` |
| `/dev/pccard0` | the a27, below |
| `/dev/ttyS0` | a trackball the game opens and never reads (no `SIGIO`) |
| `/dev/mixer`, `/dev/dsp` | through SDL_mixer |

`GX2Init` exits unless the AND of the mapped DC, VP and frame buffer
pointers is non-zero.

## Geode GX2

- **PCI** (bus 0, device 1): function 0 `0x0028100B` (host bridge),
  function 1 `0x0030100B` (graphics); registers `0x10`, `0x14`, `0x18`,
  `0x1C` of function 1 are the frame buffer, GP, DC and VP bases (all four
  non-zero, or `gfx_detect_cpu` gives up).
- **VSA:** write `0xFC53` to `0xAC1C`, then an index; read `0xAC1E`.  Index
  `0x0200`: frame buffer size in 512 KB units (16 MB here); `0x1201`: core
  clock in MHz.
- **Display:** 640×480, 16 bpp RGB565, pitch 1280.  `DC_FB_ST_OFFSET`
  (`+0x10`) is the scan-out start; `DC_LINE_CNT` (`+0x6C`) bit 30 is the
  vertical blank.  The game keeps two 640×480 pages in video memory and
  blits the back page to the primary surface at offset 0 every frame
  (`GraphRefresh`).
- **2D engine (GP):** `DST_OFFSET +0x00`, `SRC_OFFSET +0x04`, `STRIDE
  +0x08` (dst | src << 16), `WID_HEIGHT +0x0C` (w << 16 | h),
  `SRC_COLOR_FG/BG +0x10/+0x14` (colour key and mask, or the mono colours),
  `PAT_COLOR_0 +0x18`, `RASTER_MODE +0x38`, `BLT_MODE +0x40` (16-bit; the
  write starts the blit), `BLT_STATUS +0x44` (bit 2 pending, bit 0 busy,
  bit 3 room for host data), `HST_SRC +0x48`.
  - `RASTER_MODE`: bits 31..28 the format (`6` = 565), the ROP in bits 7..0
    (`0xCC` copy, `0xF0` fill), `0x800` source colour key; alpha when bits
    `0xC00000` are set: `0x740000 | a` blends a·src + (255−a)·dst, `0x460000`
    copies the source, `0x470000` keeps the destination.
  - `BLT_MODE`: `0x1` source from video memory, `0x2` source from
    `HST_SRC`, `0x40` mono source (rows padded to dwords), `0x80` byte-packed
    mono (text), `0x100` / `0x200` bottom-up / right-to-left (the offsets
    then name the last byte).
  - Bitmaps in system memory go line by line through a 2-line scratch area
    at the frame buffer's end − 16 KB; text is mono host data: ROP `0xF0`
    (the pattern colour) through a transparent mask.
  - Emulated with MMIO traps: one per register access.  A song blits about
    1,300 lines a frame (5,600 traps); the game plugin replaces the line loop
    (`gfx2_color_bitmap_to_screen_blt`) with a jump to the machine's whole-blit
    service (`e1000_api.bitmap`, `patch_jump`).

## IGS027A (`c/pcicard.c`, `c/cmdport.c`)

One exchange per frame (`main`): `lseek(fd, n)` with a running sequence,
`read(fd, buf, 0)` (the chip's packet into `g_rBufferRead`; the return
value is a status byte, `0xF0..0xFF` are fatal errors), the checks,
`lseek` again and `write(fd, buf, size + 24)` (the answer).  The commands
then run (`main_vProtect`), then `RealTimeFunction` draws the frame.  At
start-up `cmdport_vCmdPortInit` writes 0 bytes with mode 29.

**Chip → game** (`0x468` bytes):

| Offset | Field |
| --- | --- |
| `+0x00` | u32 data size (< `0x400`) |
| `+0x04` | u32 mode (shown on an a27 assert) |
| `+0x08`, `+0x0A` | error flag, error number (5 assert text, 6 cmdport error: the game halts) |
| `+0x22`, `+0x28` | a print flag and 64 bytes of text (`A27 Printf`) |
| `+0x24` | key |
| `+0x26` | checksum 1: the low byte of size + mode + the header fields + key |
| `+0x27` | checksum 2: 2 × checksum 1 + data bytes 0..11 (decoded) |
| `+0x68` | data: 16-bit command words |

The first 256 data bytes are XOR `m_baaEncodeTable[key >> 7][(key & 0xEF) +
i]` (`cmdport_vDecode`).

**Game → chip:** u32 size, u32 mode (the screen's `pcicard_vPCICardModeSet`
value, or 30), a word set to 0, two checksum bytes, a tick, the date, data
from `+0x18`.  The game only adds data in three places: `233` + its chart
summary and `234` + 800 bytes of note RAM (`song_vSongDataInit` 3/4, only
used with record files), `235` + the date (bookkeeping), `233` at the end
of the RAM test.

### Commands (`main_vProtect`)

A command is its id and its 16-bit arguments; the ones that take a struct
(26, 57, 59, 62, 71, 74, 80, 208, 218) align to 4 first.  Every argument
is consumed even when unused (205 and 204 always take 5).

| Ids | Screen |
| --- | --- |
| 0, 1, 2, 3 (region), 5, 6 | start-up (`SystemInit`, signals, common sprites, version), font, per-frame volume check |
| 7..12 | text and picture warnings |
| 13..58, 83..117 | operator menus and settings, hardware tests, bookkeeping, reset, payout |
| 59 | volumes: 8 words (day / night start, game and demo volume 0..32); all 0 until sent |
| 93 | language: 0 Traditional, 1 Simplified Chinese, 2 English |
| 118..124 | credit display (`C   credits coins/price`) |
| 125..134 | demo, IGS logo |
| 135..139 | coin page (a timer from 1200, the drum) |
| 140..144 | developer test menu |
| 145..159 | select mode (Junior / Senior, countdown) |
| 160..167 | game over |
| 168..176 | select song (22 songs, countdown) |
| 177..189, 236..239 | result, tickets |
| 190..199 | MTV (opening, staff) and the song's characters |
| 200..202 | loading screen |
| 203..214 | the song: sounds, data, sprites, 208 per frame |
| 240 | system status (0 attract, 1 game, 2 test) |

**208** (656 bytes): 32 sound triggers (wav index + 1), 30 note cursors of 8
bytes (state | lane << 6, flags, y, roll length), combo, player active,
per-lane judgement, flash and explosion bytes, score, a 0..20 gauge.  The
chip computes the song; the charts are tracks in the executable's song
table (`PercussionKids.md`).
